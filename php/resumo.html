Resumo de prova

O navegador pede, o Apache recebe, o PHP executa no servidor e devolve HTML ou JSON. O resto da matéria é como organizar esse caminho.

1. Servidor Apache e requisições HTTP

Cai obrigatoriamente na prova.
  • Cliente x servidor: o navegador é o cliente (pede e exibe). O servidor (Apache + PHP) recebe, processa e responde.
  • Apache no XAMPP: é o servidor web. Recebe a requisição; se for arquivo estático (imagem, CSS, HTML) entrega direto; se for .php, passa ao PHP executar.
  • Papel do PHP: roda no servidor, lê os dados da requisição, executa a lógica e gera a resposta. O navegador nunca vê o código PHP, só o resultado.
  • Ciclo: Request (método, URL, cabeçalhos, corpo) → processamento → Response (status, cabeçalhos, corpo).
  • localhost: o próprio computador (127.0.0.1). No XAMPP, http://localhost/ aponta para C:\xampp\htdocs. Arquivo em htdocs\loja\produtos.php abre em http://localhost/loja/produtos.php.

Servidor x navegador

PHP processa no servidor. JavaScript processa no navegador. Por isso "Exibir código-fonte" mostra só o HTML gerado.

HTML x JSON

HTML é uma página para o navegador desenhar. JSON é dado puro para outro programa ler (API). Na Aula 8, /categorias devolve HTML e /api/categorias devolve JSON com header("Content-Type: application/json") + json_encode(...).

Rota x query string x formulário

http://localhost/aula8/categorias/5?ordem=nome
                      └─ rota ──────┘ └ query string ┘
  • Parâmetro de rota: faz parte do caminho (/categorias/5). O roteador lê pelo $_SERVER["REQUEST_URI"].
  • Query string: depois do ?, em pares chave=valor separados por &. Chega em $_GET.
  • Dados do formulário (POST): vão no corpo da requisição, não aparecem na URL. Chegam em $_POST.

2. Fundamentos da linguagem

Foco do professor: interpretar pequenos trechos de código e dizer o resultado. Faça teste de mesa: anote o valor das variáveis linha a linha.
  • Estrutura: código entre <?php e ?>; instruções terminam com ;; echo imprime.
  • Variáveis: começam com $, sensíveis a maiúsculas. Tipos: int, float, string, bool, array, null.
  • Constantes: define("TAXA", 0.1) ou const TAXA = 0.1. Usadas sem $ e não mudam.
  • Strings: o . concatena. Aspas duplas leem variáveis ("Olá $nome"); aspas simples são literais.

Condicionais e laços

  • if / elseif / else: só um bloco executa, o primeiro verdadeiro.
  • switch: compara com cada case. Sem break, continua executando os cases de baixo.
  • for: for ($i = 0; $i < 3; $i++) roda com 0, 1, 2.
  • while: testa antes de cada volta; pode não rodar nenhuma vez.
  • foreach: percorre arrays. foreach ($arr as $valor) ou foreach ($arr as $chave => $valor).

Arrays

$frutas = ["maçã", "banana", "uva"];      // indexado: $frutas[0] é "maçã"
$aluno  = ["nome" => "Ana", "idade" => 20]; // associativo: $aluno["nome"]
$frutas[] = "kiwi";                          // adiciona no fim
count($frutas);                              // 4

Funções

  • return devolve o valor para quem chamou; echo só mostra na tela.
  • Parâmetro com valor padrão: function saudacao($nome, $periodo = "dia").
  • Tipagem: function soma(int $a, int $b): int.
  • Espalhamento: soma(...$array) passa cada item como um argumento (Aula 1).

require

require "arquivo.php" inclui outro arquivo; se ele não existir, erro fatal e o script para. require_once evita incluir duas vezes. (include só dá aviso e continua.)

Superglobal$_GET$_POST

  • A chave é o name do input, não o id nem o type.
  • $_SERVER: dados da requisição. REQUEST_METHOD (GET, POST...) e REQUEST_URI (caminho com query string).
  • Tudo chega como string. Converta com (int) e (float). Cuidado: (float) "12,50" vira 12; a Lista 3 usa str_replace(",", ".", ...) antes.
  • Uma requisição pode ter os dois: action="salvar.php?id=7" method="POST" dá $_GET["id"] e os campos em $_POST.

Validação básica

isset($_POST["nome"], ...)
Confere se os campos foram enviados (existem e não são null). Ex. 5 da Lista 2.
$_POST["nome"] ?? ""
Usa o valor padrão se a chave não existir.
trim()
Tira espaços das pontas, para " " contar como vazio.
is_numeric()
Confere se o texto é um número válido antes de converter.
htmlspecialchars()
Ao exibir o que o usuário digitou, transforma HTML em texto (evita XSS).

4. Arquitetura MVC e organização de projetos

Foco do professor: compreender o caminho de uma requisição até a apresentação de uma página HTML.
ModelDados e regras de negócio. Classes como Produto, Categoria, com salvar().
ViewApresentação: o HTML. app/Views/layout.php e categorias/index.php.
ControllerRecebe a requisição, chama o Model e escolhe a View. CategoriaController.

O caminho de GET /aula8/categorias

  1. Apache + .htaccessNão é arquivo real, então RewriteRule ^ index.php manda para o index.php.
  2. index.php (rotas)Carrega vendor/autoload.php, limpa a URI (strtok, tira /aula8, rtrim) e confere o REQUEST_METHOD.
  3. Controller(new CategoriaController())->index() pega os dados e chama o Render com compact('titulo', 'categorias').
  4. ViewRender faz extract, renderiza a view com ob_start e coloca dentro do layout.php.
  5. RespostaO HTML volta pelo Apache até o navegador.

Mesma URI, método diferente, ação diferente: GET /api/categorias chama list() (JSON) e POST /api/categorias chama create().

require, autoload e Composer

  • Sem Composer (Aula 4, Listas 3 e 4): cada arquivo faz require_once das classes que usa.
  • Com Composer (Aulas 8 e 9): um único require_once __DIR__ . "/vendor/autoload.php"; e as classes são carregadas sozinhas quando usadas.
  • Mudou o autoload do composer.json? Rode composer dump-autoload.

PSR-4 e namespaces

"autoload": { "psr-4": { "App\\": "app/" } }

App\Controllers\CategoriaController  ──►  app/Controllers/CategoriaController.php
  • PSR = PHP Standards Recommendation (PHP-FIG). PSR-4 = padrão de autoload que liga namespace a pasta.
  • namespace App\Controllers; é a primeira instrução do arquivo da classe.
  • use App\Controllers\CategoriaController; só importa o nome. Não carrega arquivo: quem carrega é o autoload.

Pegadinhas de prova

  • PHP roda no servidor; o navegador só recebe HTML ou JSON.
  • localhost = htdocs. A palavra htdocs não aparece na URL.
  • Rota fica antes do ?; query string fica depois e vai para $_GET.
  • A chave do $_POST é o name do input.
  • Tudo do formulário é string; vírgula decimal quebra o (float).
  • == compara valor; === compara valor e tipo.
  • switch sem break continua executando os cases seguintes.
  • Índice de array começa no 0.
  • echo mostra; return devolve.
  • require sem o arquivo = erro fatal; use não é require.
